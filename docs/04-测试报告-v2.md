### 3.4 失败用例分析

#### 类型一：URL 中文编码问题（8 个用例）

**错误信息**：`TypeError: Request path contains unescaped characters`

**影响用例**：
- `poem-search.test.js`：5 个用例（关键词搜索、originalKeyword、高亮、分页、繁简搜索）
- `authors.test.js`：1 个用例（按朝代筛选 dynasty=唐）
- `poems.test.js`：2 个用例（按朝代筛选、组合筛选）

**根因分析**：测试代码中直接使用中文字符构造 URL 路径（如 `/api/poems/search?q=月`），未使用 `encodeURIComponent()` 进行编码。supertest 底层的 superagent 库在 Node.js 环境下拒绝发送包含未编码字符的请求。

**注意**：通过 curl 使用 URL 编码后的中文参数验证，所有 API 均正常返回正确结果（详见第四节）。此问题属于测试代码缺陷，不影响 API 实际功能。

#### 类型二：分类数据重复（1 个用例）

**错误信息**：`AssertionError: expected 1523 to be 1576 // Object.is equality`

**影响用例**：`categories.test.js` > 分类名称不重复

**根因分析**：数据库中存在 1576 条分类记录，但仅有 1523 个不重复名称，即存在 53 个重复的分类名称。这是数据源本身的问题（不同朝代或来源存在同名分类），非二期代码引入的缺陷。

### 3.5 AC13 结论

**部分通过**。35 个用例中 26 个通过，9 个失败。失败原因分析：
- 8 个失败为测试代码 URL 编码缺陷（非业务逻辑问题），通过 curl 编码验证 API 功能均正常
- 1 个失败为数据源质量问题（分类重复），非二期代码引入

## 六、缺陷记录

### BUG-001：测试代码 URL 中文未编码导致 supertest 请求失败

| 项目 | 内容 |
|---|---|
| 编号 | BUG-001 |
| 严重度 | 低（P3 - 测试代码缺陷，不影响业务） |
| 影响范围 | 8 个自动化测试用例 |
| 复现步骤 | 执行 `npm test`，观察 poem-search / authors / poems 测试文件 |
| 期望结果 | 测试用例使用 `encodeURIComponent()` 编码中文参数，所有用例通过 |
| 实际结果 | 测试代码直接拼接中文字符到 URL，supertest 抛出 `ERR_UNESCAPED_CHARACTERS` |
| 修复建议 | 在测试代码中对中文参数使用 `encodeURIComponent()` 编码，如：`/api/poems/search?q=${encodeURIComponent('月')}` |

### BUG-002：分类数据存在重复名称

| 项目 | 内容 |
|---|---|
| 编号 | BUG-002 |
| 严重度 | 低（P3 - 数据质量问题） |
| 影响范围 | categories API 返回 1576 条记录，其中 53 个名称重复 |
| 复现步骤 | 调用 GET /api/categories，检查返回数据中 name 字段的唯一性 |
| 期望结果 | 分类名称全局唯一，无重复 |
| 实际结果 | 1576 条记录中仅 1523 个不重复名称，存在 53 个重名分类 |
| 修复建议 | 在分类查询 SQL 中添加 `DISTINCT` 去重，或在数据导入阶段合并同名分类 |
