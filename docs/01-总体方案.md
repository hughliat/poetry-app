## 一、项目背景与目标

### 1.1 背景

中国古典诗词是中华文化的瑰宝，现存唐诗宋词数量超过十万首。然而，现有诗词资源多以学术论文或大型数据库形式存在，缺少面向普通爱好者的轻量级阅读工具。chinese-poetry 开源项目提供了完整的结构化诗词数据集（CC0/公有领域），为构建此类应用奠定了数据基础。

### 1.2 一句话目标

构建一个轻量级的诗词阅读与搜索 Web 应用，让用户可以浏览、检索中国古典诗词（唐诗宋词为主），获得沉浸式阅读体验。

### 1.3 成功标准

| 维度 | 标准 | 度量方式 |
|---|---|---|
| 数据规模 | 收录 >= 1 万首诗词 | 数据库记录数统计 |
| 功能可用 | 浏览、搜索、详情、随机推荐四项核心功能本地可演示 | 人工逐项验证 |
| 搜索性能 | 关键词搜索响应时间 <= 500ms | 本地环境实测 |
| 用户体验 | 界面简洁、古典风格、响应式布局 | 人工评审 |

## 二、范围与边界

### 2.1 MVP 包含（做什么）

| 功能 | 说明 |
|---|---|
| 诗词浏览 | 按作者、朝代、诗体/词牌分类浏览，支持分页 |
| 关键词搜索 | 按标题、作者、正文内容进行模糊搜索 |
| 诗词详情 | 展示完整诗词内容，含标题、作者、朝代、正文、注释（如有） |
| 随机推荐 | 随机展示一首诗词，支持"换一首"操作 |

### 2.2 MVP 不包含（明确不做）

| 排除项 | 原因 |
|---|---|
| 用户系统（注册/登录/收藏） | MVP 聚焦阅读，用户系统属二期范围 |
| AI 生成（诗词赏析/配图） | 技术复杂度高，非核心阅读需求 |
| 社区互动（评论/分享/讨论） | 需要用户系统前置，二期考虑 |
| 公网部署 | MVP 阶段本地运行演示即可，不投入服务器成本 |
| 诗词背诵/默写功能 | 教育类需求，非 MVP 阅读场景 |
| 多语言/繁体切换 | 数据源为简体中文，二期可扩展 |

### 2.3 二期功能展望（仅记录，不在本期实施）

- 用户收藏与阅读历史
- 诗词赏析与 AI 配图
- 收藏夹分享
- 繁体/简体切换
- 公网部署与 CDN 加速

## 三、用户画像与使用场景

### 3.1 用户画像

| 画像 | 描述 |
|---|---|
| 诗词爱好者（主要） | 对中国古典诗词有兴趣，日常阅读欣赏，希望快速找到某首诗或某位作者的作品 |
| 学生/教师（次要） | 学习或教学中需要查阅诗词，按关键词或作者检索特定内容 |
| 文化探索者（次要） | 对诗词不太熟悉，希望通过随机推荐发现新作品，培养兴趣 |

### 3.2 典型使用场景

**场景一：按作者浏览作品集**

> 小李是诗词爱好者，想阅读杜甫的全部诗作。他打开应用，在作者分类中选择"杜甫"，系统展示杜甫所有诗词列表。他点击感兴趣的标题，进入详情页阅读完整内容。

**场景二：关键词搜索**

> 王老师正在备课，需要找包含"月"字的诗词用于教学。她在搜索框输入"月"，系统返回所有包含该关键词的诗词列表。她浏览搜索结果，点击查看详情，选取适合教学的内容。

**场景三：随机发现**

> 小张对诗词了解不多，只是好奇打开应用看看。他点击"随机推荐"按钮，系统展示一首随机的诗词。他阅读后觉得不错，点击"换一首"继续探索，不知不觉读了十几首。

## 四、技术路线

### 4.1 整体架构

```
┌─────────────────────────────────────────────────┐
│                   浏览器（用户）                    │
└──────────────────────┬──────────────────────────┘
                       │ HTTP/REST
┌──────────────────────▼──────────────────────────┐
│              前端（Vue 3 + Vite）                  │
│  ┌──────────┐  ┌──────────┐  ┌───────────────┐  │
│  │ Vue Router│  │ 页面组件  │  │ 古典风格 CSS  │  │
│  └──────────┘  └──────────┘  └───────────────┘  │
└──────────────────────┬──────────────────────────┘
                       │ REST API (JSON)
┌──────────────────────▼──────────────────────────┐
│            后端（Node.js + Express）               │
│  ┌──────────┐  ┌──────────┐  ┌───────────────┐  │
│  │ 路由层   │  │ 业务逻辑  │  │ 数据访问层    │  │
│  └──────────┘  └──────────┘  └───────────────┘  │
└──────────────────────┬──────────────────────────┘
                       │ SQL
┌──────────────────────▼──────────────────────────┐
│              数据库（SQLite）                      │
│  ┌──────────────────────────────────────────┐    │
│  │ poems / authors / dynasties / metadata   │    │
│  └──────────────────────────────────────────┘    │
└─────────────────────────────────────────────────┘
                       ▲
                       │ JSON 数据导入
┌──────────────────────┴──────────────────────────┐
│         chinese-poetry 数据集（JSON 文件）         │
└─────────────────────────────────────────────────┘
```

### 4.2 前端架构

| 技术 | 版本要求 | 选型理由 |
|---|---|---|
| Vue 3 | >= 3.3 | 组合式 API 更简洁，生态成熟，社区活跃 |
| Vite | >= 5.0 | 开发热更新极快，构建性能优于 Webpack |
| Vue Router | >= 4.0 | Vue 3 官方路由方案，支持嵌套路由与动态参数 |
| 原生 CSS | — | 不使用 UI 框架，保持轻量，自定义古典风格更灵活 |

**前端页面规划：**

| 页面 | 路由 | 功能 |
|---|---|---|
| 首页 | `/` | 应用入口，展示随机推荐诗词、快捷入口 |
| 浏览页 | `/browse` | 按朝代/作者/诗体分类浏览 |
| 搜索结果页 | `/search?q=xxx` | 展示搜索命中列表 |
| 诗词详情页 | `/poem/:id` | 展示单首诗词完整内容 |

### 4.3 后端架构

| 技术 | 版本要求 | 选型理由 |
|---|---|---|
| Node.js | >= 18 LTS | 前后端统一 JavaScript，降低开发成本 |
| Express | >= 4.18 | 最成熟的 Node.js Web 框架，中间件生态丰富 |
| better-sqlite3 | >= 11.0 | 同步 API 性能优异，比异步 sqlite3 更适合读多写少场景 |

**REST API 设计（核心接口）：**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/poems` | 获取诗词列表（支持分页、筛选） |
| GET | `/api/poems/:id` | 获取单首诗词详情 |
| GET | `/api/poems/random` | 随机获取一首诗词 |
| GET | `/api/poems/search?q=keyword` | 关键词搜索诗词 |
| GET | `/api/authors` | 获取作者列表 |
| GET | `/api/dynasties` | 获取朝代列表 |
| GET | `/api/categories` | 获取分类（诗体/词牌） |

### 4.4 数据流

```
chinese-poetry JSON 文件
    │
    ▼  [npm run init-data]
数据清洗与校验脚本（Node.js）
    │  - 统一字段格式
    │  - 过滤无效数据
    │  - 提取作者/朝代/分类
    ▼
SQLite 数据库（poetry.db）
    │
    ▼  [后端启动时加载]
Express API 层（只读查询）
    │
    ▼  [前端 fetch 请求]
Vue 3 页面渲染
```

### 4.5 关键技术决策

| 决策 | 理由 |
|---|---|
| SQLite 而非 MySQL/PostgreSQL | MVP 本地运行，零配置、单文件部署，数据量（10 万级）完全可承载 |
| better-sqlite3 而非 sqlite3 | 同步 API 避免回调/Promise 开销，读性能更优 |
| 原生 CSS 而非 UI 框架 | 古典风格需高度定制，UI 框架反而增加覆盖成本；保持轻量 |
| 前后端分离 | 职责清晰，前端可独立开发调试，二期可扩展为 SPA 部署 |

## 五、数据方案

### 5.1 数据源介绍

[chinese-poetry](https://github.com/chinese-poetry/chinese-poetry) 是 GitHub 上最大的中国古典诗词开源数据集，采用 CC0/公有领域协议，可自由使用。

### 5.2 数据规模

| 类别 | 数量级 | 说明 |
|---|---|---|
| 唐诗 | ~57,000 首 | 来自 `chinese-poetry/唐诗` 目录 |
| 宋词 | ~21,000 首 | 来自 `chinese-poetry/宋词` 目录 |
| 五代诗词 | ~数百首 | 可选导入 |
| 其他 | 视情况 | 元曲等，二期可扩展 |

MVP 目标导入量：**>= 1 万首**（优先唐诗 + 宋词），确保满足成功标准。

### 5.3 字段结构

**唐诗（tangshi）典型 JSON 结构：**

```json
{
  "title": "静夜思",
  "author": "李白",
  "dynasty": "唐",
  "content": ["床前明月光，", "疑是地上霜。", "举头望明月，", "低头思故乡。"],
  "id": "tang-001"
}
```

**宋词（songci / ci）典型 JSON 结构：**

```json
{
  "rhythmic": "水调歌头",
  "author": "苏轼",
  "dynasty": "宋",
  "paragraphs": ["明月几时有，把酒问青天。", "..."],
  "id": "song-ci-001"
}
```

**注意：** 唐诗和宋词的 JSON 字段命名不完全一致（`title` vs `rhythmic`，`content` vs `paragraphs`），需要在导入时统一。

### 5.4 数据库表设计（概要）

| 表名 | 主要字段 | 说明 |
|---|---|---|
| `dynasties` | id, name | 朝代字典 |
| `authors` | id, name, dynasty_id | 作者表，关联朝代 |
| `poems` | id, title, author_id, dynasty_id, category, content (TEXT), source | 诗词主表 |
| `poem_fts` | (FTS5 虚拟表) | 全文搜索索引（title + author + content） |

### 5.5 数据导入策略

1. **提取**：读取 chinese-poetry 仓库中 `唐诗/` 和 `宋词/` 目录下的 JSON 文件
2. **清洗**：
   - 统一字段命名（`rhythmic` -> `title`，`paragraphs` -> `content`）
   - 过滤空内容、无效记录的条目
   - 去重（按 title + author 组合判断）
3. **转换**：
   - 提取不重复的作者，写入 `authors` 表
   - 提取朝代信息，写入 `dynasties` 表
   - 诗词正文数组拼接为字符串（以换行符分隔）
4. **加载**：批量 INSERT 到 SQLite，使用事务保证原子性
5. **索引**：创建 FTS5 全文搜索索引，加速关键词检索

导入脚本通过 `npm run init-data` 一键执行，输出导入统计信息（成功数、跳过数、失败数）。

## 七、非功能需求

### 7.1 性能

| 指标 | 要求 | 说明 |
|---|---|---|
| 搜索响应时间 | <= 500ms | 本地 SQLite + FTS5 索引 |
| 列表页加载时间 | <= 1s | 分页加载，每页 20 条 |
| 首屏渲染时间 | <= 2s | Vite 构建优化，资源懒加载 |
| 数据库导入时间 | <= 60s | 一次性操作，使用批量事务 |

### 7.2 可用性

| 指标 | 要求 |
|---|---|
| 界面风格 | 古典中式风格，配色素雅，排版舒适 |
| 响应式布局 | 适配桌面（>= 1024px）和平板（>= 768px）两种宽度 |
| 操作反馈 | 搜索无结果时给出友好提示，加载中有视觉指示 |
| 错误处理 | 后端异常返回统一错误格式，前端展示可读错误页面 |

### 7.3 兼容性

| 维度 | 要求 |
|---|---|
| 浏览器 | Chrome >= 90、Firefox >= 90、Safari >= 15、Edge >= 90 |
| 运行环境 | Node.js >= 18，npm >= 8 |
| 操作系统 | macOS、Linux、Windows（本地开发均可运行） |

### 7.4 可维护性

| 维度 | 要求 |
|---|---|
| 代码规范 | ESLint 统一检查，关键逻辑必须注释 |
| 目录结构 | 遵循 AGENT.md 定义的目录规范 |
| 数据导入 | 一键脚本 `npm run init-data`，可重复执行 |
| 可扩展性 | 后端分层（路由/业务/数据），便于二期扩展 |

## 十、验收标准

以下标准均可量化、可测试，作为 MVP 交付的最终判定依据：

| 编号 | 验收项 | 标准 | 测试方法 |
|---|---|---|---|
| AC1 | 数据完整性 | SQLite 中诗词记录数 >= 10,000 条 | `SELECT COUNT(*) FROM poems;` |
| AC2 | 浏览功能 | 可按朝代、作者筛选诗词列表，分页正常（每页 20 条） | 人工操作验证 |
| AC3 | 搜索功能 | 输入关键词后返回匹配结果，响应时间 <= 500ms | 使用 10 个典型关键词测试，记录响应时间 |
| AC4 | 详情功能 | 点击诗词条目可跳转详情页，展示标题、作者、朝代、正文 | 人工操作验证 |
| AC5 | 随机推荐 | 点击按钮展示随机诗词，连续 5 次不完全重复 | 人工操作验证 |
| AC6 | 界面风格 | 古典风格、配色素雅、响应式布局在 1024px 和 768px 下正常显示 | 人工评审 |
| AC7 | 本地可运行 | 执行 `npm install` + `npm run init-data` + `npm run dev` 即可启动并演示全部功能 | 在干净环境中复现 |
| AC8 | 代码规范 | ESLint 检查零 error | `npm run lint` |
