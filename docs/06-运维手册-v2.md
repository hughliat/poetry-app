## 二、系统架构

### 2.1 架构概览

poetry-app v2.0.0 在一期架构基础上新增了繁简转换、收藏功能与自动化测试，整体架构保持不变。

```
┌──────────────────────────────────────────────────────────┐
│                      浏览器（用户）                         │
│  ┌────────────────────────────────────────────────────┐  │
│  │ sessionStorage: 繁简切换状态                         │  │
│  │ localStorage:  收藏数据                              │  │
│  └────────────────────────────────────────────────────┘  │
└───────────────────────────┬──────────────────────────────┘
                            │ HTTP
┌───────────────────────────▼──────────────────────────────┐
│               前端（Vue 3 + Vite） :5173                   │
│  ┌───────────┐  ┌───────────┐  ┌──────────────────────┐  │
│  │Vue Router │  │ 5 个页面   │  │ opencc-js 繁简转换    │  │
│  │(含收藏页) │  │(含收藏页) │  │ + 4 级响应式断点      │  │
│  └───────────┘  └───────────┘  └──────────────────────┘  │
└───────────────────────────┬──────────────────────────────┘
                            │ REST API (JSON)
┌───────────────────────────▼──────────────────────────────┐
│             后端（Node.js + Express） :3000                │
│  ┌──────────┐  ┌──────────────┐  ┌────────────────────┐  │
│  │ 路由层   │  │ 业务逻辑层   │  │ 数据访问层(DAL)     │  │
│  └──────────┘  └──────────────┘  └────────────────────┘  │
│  ┌────────────────────────────────────────────────────┐  │
│  │ start.js（启动入口） ← app.js（Express 应用导出）    │  │
│  └────────────────────────────────────────────────────┘  │
└───────────────────────────┬──────────────────────────────┘
                            │ SQL (better-sqlite3)
┌───────────────────────────▼──────────────────────────────┐
│                   数据库（SQLite）                          │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ dynasties / authors / poems / poem_fts(FTS5)        │  │
│  └─────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

### 2.2 技术组件

| 组件 | 技术 | 端口 | 说明 |
|---|---|---|---|
| 前端 | Vue 3 + Vite | :5173（开发） | SPA 单页应用 |
| 繁简转换 | opencc-js | — | 前端本地转换，无需后端支持 |
| 后端 | Node.js + Express | :3000 | REST API 服务 |
| 启动入口 | start.js | :3000 | **v2.0.0 变更**：从 app.js 分离 listen |
| 数据库 | SQLite (better-sqlite3) | — | 单文件数据库（~304MB） |
| 全文索引 | FTS5 | — | SQLite 全文搜索扩展 |
| 测试 | Vitest + Supertest | — | **v2.0.0 新增**：35 个自动化测试用例 |

### 2.3 后端三层架构

| 层次 | 目录 | 职责 |
|---|---|---|
| 路由层 | `src/server/routes/` | 接收请求、参数校验、调用业务层 |
| 业务逻辑层 | `src/server/services/` | 组装查询条件、数据处理、分页计算 |
| 数据访问层 | `src/server/dao/` | 执行 SQL 查询、返回原始数据 |

### 2.4 v2.0.0 架构变更说明

| 变更项 | v1.0.0 | v2.0.0 | 说明 |
|---|---|---|---|
| 后端启动入口 | `app.js`（直接 listen） | `start.js`（调用 app.listen） | app.js 仅导出 Express 应用，便于测试导入 |
| 前端页面数 | 4 个 | 5 个 | 新增收藏列表页 /favorites |
| 前端依赖 | Vue 3 + Vite + Vue Router | + opencc-js | 繁简转换 |
| 后端开发依赖 | — | + vitest + supertest | 自动化测试 |
| 客户端存储 | 无 | sessionStorage + localStorage | 繁简切换状态 + 收藏数据 |

## 三、部署步骤

### 3.1 本地部署

#### 完整部署步骤（v2.0.0 更新）

```bash
# Step 1: 环境检查
node --version   # 确认 >= 18
npm --version    # 确认 >= 8
git --version    # 确认 Git 可用

# Step 2: 获取项目代码
git clone <project-repo-url> poetry-app
cd poetry-app

# Step 3: 安装依赖（v2.0.0 包含新增依赖）
npm run install:all
# 前端依赖：Vue 3, Vite, Vue Router, opencc-js ^1.0.0
# 后端依赖：Express, better-sqlite3, cors
# 后端开发依赖：vitest ^1.0.0, supertest ^6.0.0

# Step 4: 初始化数据（首次部署或重建数据库时执行）
npm run init-data
# 自动下载 chinese-poetry 数据集（约 200MB，需网络）
# 执行 ETL：读取 JSON -> 字段映射 -> 过滤去重 -> 批量导入 SQLite
# 预计耗时 1-2 分钟

# Step 5: 运行自动化测试（v2.0.0 新增步骤）
npm test
# 预期输出：35/35 测试用例全部通过
# 测试覆盖 7 个 API 接口，验证后端功能正确性
# 首次部署建议执行此步骤确认环境正常

# Step 6: 启动开发服务
npm run dev
# 前端：http://localhost:5173
# 后端：http://localhost:3000（通过 start.js 启动）
```

#### 生产模式部署（本地）

```bash
# Step 1-5 同上（安装依赖 + 数据初始化 + 运行测试）

# Step 6: 构建前端
npm run build
# 产物输出到 src/client/dist/

# Step 7: 生产模式启动（v2.0.0 使用 start.js）
npm start
# 后端通过 start.js 启动，服务前端构建产物
# 访问地址：http://localhost:3000
```

#### 从 v1.0.0 升级部署

```bash

# Ctrl+C 终止 npm run dev 进程

# Step 2: 获取 v2.0.0 代码
git pull origin main    # 或 git checkout v2.0.0

# Step 3: 重新安装依赖（安装二期新增依赖）
npm run install:all

# Step 4: 数据库无需变更（v2.0.0 未修改数据库结构）

# Step 5: 运行自动化测试
npm test
# 预期：35/35 通过

# Step 6: 启动服务
npm run dev
```

## 五、配置说明

### 5.1 环境变量

| 变量名 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3000` | 后端 API 服务端口 |
| `POETRY_DB_PATH` | `data/poetry.db` | SQLite 数据库文件路径（v2.0.0 优化了路径解析逻辑） |
| `NODE_ENV` | `development` | 运行环境，设为 `production` 启用生产模式 |
| `VITEST` | — | Vitest 测试运行时自动设置为 `test`，无需手动配置 |

### 5.2 数据库路径配置

数据库文件默认位于 `data/poetry.db`。v2.0.0 优化了路径解析逻辑（OBS-002），使用更健壮的绝对/相对路径处理。如需自定义路径，设置环境变量：

```bash
# 使用自定义数据库路径
export POETRY_DB_PATH=/custom/path/poetry.db
npm run dev
```

### 5.3 前端配置

前端开发服务器默认运行在 `:5173`，通过 Vite 配置文件管理。后端 API 地址在前端 `src/client/api/index.js` 中配置。

### 5.4 客户端存储说明（v2.0.0 新增）

| 存储类型 | 用途 | 持久性 | 说明 |
|---|---|---|---|
| sessionStorage | 繁简切换状态 | 标签页级别（关闭标签页后重置） | 存储当前选择的文字模式（简体/繁体） |
| localStorage | 收藏诗词数据 | 持久（除非用户清除浏览器数据） | 存储收藏的诗词 ID 列表 |

### 6.5 数据备份

SQLite 数据库为单文件，备份非常简单：

```bash
# 方法一：直接复制数据库文件
cp data/poetry.db data/poetry.db.backup

# 方法二：使用 sqlite3 的 .backup 命令（更安全，避免并发写入问题）
sqlite3 data/poetry.db ".backup 'data/poetry.db.backup'"

# 方法三：定时备份（crontab 示例）
# 每天凌晨 2 点备份
# 0 2 * * * cp /path/to/data/poetry.db /path/to/backup/poetry-$(date +\%Y\%m\%d).db
```

**备份建议：**

| 项目 | 建议 |
|---|---|
| 备份频率 | MVP 阶段数据为只读，初始化后无需频繁备份；生产环境建议每日备份 |
| 备份位置 | 本地备份 + 异地存储（如对象存储） |
| 恢复方式 | 将备份文件复制回 `data/poetry.db` 即可 |
| 收藏数据 | 用户收藏存储在浏览器 localStorage，无法通过服务端备份；如需备份，可通过浏览器开发者工具导出 |

## 八、常见故障处置

### 8.1 后端启动失败

#### 故障现象：端口占用

```
Error: listen EADDRINUSE: address already in use :::3000
```

**处置方法：**

```bash
# 查找占用端口的进程
lsof -i :3000
# 或
netstat -tlnp | grep 3000

# 终止占用进程
kill -9 <PID>

# 或修改端口
export PORT=3001
npm run dev:server
```

#### 故障现象：依赖缺失

```
Error: Cannot find module 'express'
```

**处置方法：**

```bash
cd src/server
npm install
```

#### 故障现象：better-sqlite3 编译失败

```
Error: better-sqlite3 安装失败，原生编译错误
```

**处置方法：**

```bash
# 重新编译原生模块
npm rebuild better-sqlite3

# 若仍失败，检查构建工具
# macOS: xcode-select --install
# Linux: sudo apt-get install build-essential python3
# Windows: npm install --global windows-build-tools
```

#### 故障现象：start.js 启动报错（v2.0.0 新增）

```
Error: Cannot find module './app'
```

**处置方法：**

```bash
# 确认 start.js 和 app.js 都在 src/server/ 目录下
ls -la src/server/start.js src/server/app.js

# 确认 app.js 正确导出了 Express 应用
# start.js 通过 require('./app') 导入应用实例并调用 app.listen()
```

### 8.2 前端启动失败

#### 故障现象：依赖缺失

```
Error: Cannot find module 'vue'
```

**处置方法：**

```bash
cd src/client
npm install
```

#### 故障现象：opencc-js 未安装（v2.0.0 新增）

```
Error: Cannot find module 'opencc-js'
```

**处置方法：**

```bash
cd src/client
npm install opencc-js
```

#### 故障现象：Vite 配置错误

```
Failed to load config file: vite.config.js
```

**处置方法：**

```bash
# 检查 vite.config.js 语法是否正确
# 确认 @vitejs/plugin-vue 已安装
cd src/client
npm install @vitejs/plugin-vue --save-dev
```

#### 故障现象：端口 5173 被占用

**处置方法：**

```bash
# 查找并终止占用进程
lsof -i :5173
kill -9 <PID>
```

### 8.3 数据库连接失败

#### 故障现象：数据库文件不存在

```
Error: ENOENT: no such file or directory, open 'data/poetry.db'
```

**处置方法：**

```bash
# 检查数据库文件是否存在
ls -la data/poetry.db

# 若不存在，重新初始化数据
npm run init-data
```

#### 故障现象：数据库文件损坏

```
Error: database disk image is malformed
```

**处置方法：**

```bash
# 1. 从备份恢复
cp data/poetry.db.backup data/poetry.db

# 2. 若无备份，重新初始化
rm data/poetry.db
npm run init-data
```

#### 故障现象：路径配置错误

**处置方法：**

```bash
# 检查环境变量
echo $POETRY_DB_PATH

# 确保路径正确且文件存在
# 使用默认路径：取消设置 POETRY_DB_PATH
unset POETRY_DB_PATH
```

### 8.4 数据导入失败

#### 故障现象：网络问题（git clone 失败）

```
Error: git clone 失败，无法下载 chinese-poetry 数据集
```

**处置方法：**

```bash
# 检查网络连接
ping github.com

# 手动下载数据集
cd data
git clone --depth 1 https://github.com/chinese-poetry/chinese-poetry.git
cd ..

# 重新执行导入（跳过下载步骤）
npm run init-data
```

#### 故障现象：磁盘空间不足


### 8.6 localStorage 不可用处理（v2.0.0 新增）

#### 故障现象：收藏功能不工作

用户点击收藏按钮后，刷新页面收藏数据丢失，或浏览器控制台报错：

```
DOMException: Failed to read the 'localStorage' property from 'Window'
```

**可能原因与处置方法：**

| 原因 | 处置方法 |
|---|---|
| 浏览器隐私模式/无痕模式 | 部分浏览器无痕模式下 localStorage 不可用或重启后清除，属于正常行为。提示用户切换到普通浏览模式 |
| localStorage 配额已满 | 收藏数据仅存储诗词 ID，占用空间极小（通常 < 10KB）。如确实满额，引导用户清除部分浏览器数据 |
| 浏览器禁用了 Cookie/存储 | 引导用户在浏览器设置中启用 localStorage / 网站数据 |
| 用户清除了浏览器数据 | 收藏数据会丢失，属于预期行为。提示用户收藏数据存储在浏览器本地，清除浏览器数据会丢失收藏 |

#### 故障现象：繁简切换状态不持久

**处置方法：**

繁简切换状态存储在 sessionStorage，关闭标签页后会重置为默认值（简体）。这是设计行为，非故障。如需跨标签页持久化，可考虑后续版本改用 localStorage 存储。

## 十、安全建议

### 10.1 当前阶段

| 项目 | 说明 |
|---|---|

| 客户端存储安全 | localStorage / sessionStorage 仅存储收藏 ID 和繁简偏好，无敏感数据 |

### 10.2 生产环境建议

若后续将应用部署到公网，建议采取以下安全措施：

| 安全维度 | 建议措施 | 说明 |
|---|---|---|
| HTTPS | 配置 SSL 证书（Let's Encrypt 免费） | 加密传输，防止中间人攻击 |
| CORS | 配置允许的域名白名单 | 限制跨域请求来源 |
| 速率限制 | 使用 `express-rate-limit` 中间件 | 防止 API 滥用和 DDoS |
| 输入校验 | 对所有用户输入进行校验和转义 | 防止 SQL 注入和 XSS |
| 请求体大小限制 | 配置 `express.json({ limit: '10kb' })` | 防止大请求体攻击 |
| 安全头 | 使用 `helmet` 中间件 | 自动设置安全相关 HTTP 头 |
| 依赖更新 | 定期 `npm audit` 检查依赖漏洞 | 及时修复已知安全漏洞 |
| 数据库权限 | SQLite 文件设置为只读 | 防止意外写入 |
| XSS 防护 | localStorage 中的收藏数据不直接渲染为 HTML | 收藏 ID 为数字，XSS 风险极低 |
