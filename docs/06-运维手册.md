## 二、系统架构

### 2.1 架构概览

poetry-app 采用前后端分离架构，后端提供 REST API，前端为 SPA 单页应用。详细架构设计参见 `docs/03-开发设计.md` 第三章。

```
┌──────────────────────────────────────────────────────┐
│                    浏览器（用户）                       │
└─────────────────────────┬────────────────────────────┘
                          │ HTTP
┌─────────────────────────▼────────────────────────────┐
│               前端（Vue 3 + Vite） :5173               │
│  ┌───────────┐  ┌───────────┐  ┌──────────────────┐  │
│  │Vue Router │  │ 4 个页面   │  │ 古典风格 CSS      │  │
│  └───────────┘  └───────────┘  └──────────────────┘  │
└─────────────────────────┬────────────────────────────┘
                          │ REST API (JSON)
┌─────────────────────────▼────────────────────────────┐
│             后端（Node.js + Express） :3000            │
│  ┌──────────┐  ┌──────────────┐  ┌────────────────┐  │
│  │ 路由层   │  │ 业务逻辑层   │  │ 数据访问层(DAL) │  │
│  └──────────┘  └──────────────┘  └────────────────┘  │
└─────────────────────────┬────────────────────────────┘
                          │ SQL (better-sqlite3)
┌─────────────────────────▼────────────────────────────┐
│                 数据库（SQLite）                        │
│  ┌───────────────────────────────────────────────┐    │
│  │ dynasties / authors / poems / poem_fts(FTS5)  │    │
│  └───────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────┘
```

### 2.2 技术组件

| 组件 | 技术 | 端口 | 说明 |
|---|---|---|---|
| 前端 | Vue 3 + Vite | :5173（开发） | SPA 单页应用 |
| 后端 | Node.js + Express | :3000 | REST API 服务 |
| 数据库 | SQLite (better-sqlite3) | — | 单文件数据库（~304MB） |
| 全文索引 | FTS5 | — | SQLite 全文搜索扩展 |

### 2.3 后端三层架构

| 层次 | 目录 | 职责 |
|---|---|---|
| 路由层 | `src/server/routes/` | 接收请求、参数校验、调用业务层 |
| 业务逻辑层 | `src/server/services/` | 组装查询条件、数据处理、分页计算 |
| 数据访问层 | `src/server/dao/` | 执行 SQL 查询、返回原始数据 |

## 三、部署步骤

### 3.1 本地部署（MVP 阶段）

#### 完整部署步骤

```bash
# Step 1: 环境检查
node --version   # 确认 >= 18
npm --version    # 确认 >= 8
git --version    # 确认 Git 可用

# Step 2: 获取项目代码
git clone <project-repo-url> poetry-app
cd poetry-app

# Step 3: 安装依赖
npm run install:all
# 分别安装 src/server 和 src/client 的 node_modules

# Step 4: 初始化数据
npm run init-data
# 自动下载 chinese-poetry 数据集（约 200MB，需网络）
# 执行 ETL：读取 JSON -> 字段映射 -> 过滤去重 -> 批量导入 SQLite
# 预计耗时 1-2 分钟

# Step 5: 启动开发服务
npm run dev
# 前端：http://localhost:5173
# 后端：http://localhost:3000
```

#### 生产模式部署（本地）

```bash
# Step 1-4 同上（安装依赖 + 数据初始化）

# Step 5: 构建前端
npm run build
# 产物输出到 src/client/dist/

# Step 6: 生产模式启动
npm start
# 后端以生产模式启动，服务前端构建产物
# 访问地址：http://localhost:3000
```

#### 部署验证清单

| 验证项 | 操作 | 预期结果 |
|---|---|---|
| 后端 API | `curl http://localhost:3000/api/dynasties` | 返回朝代列表 JSON |
| 前端页面 | 浏览器打开 http://localhost:5173 | 显示首页 |
| 数据完整性 | `sqlite3 data/poetry.db "SELECT COUNT(*) FROM poems;"` | >= 10,000 |

pm2 delete poetry-app

### 6.3 日志查看

```bash
# 开发模式：日志直接输出到终端（stdout/stderr）

# PM2 管理时：
pm2 logs poetry-app              # 实时查看日志
pm2 logs poetry-app --lines 100  # 查看最近 100 行

# ~/.pm2/logs/poetry-app-out.log
# ~/.pm2/logs/poetry-app-error.log
```

### 6.4 数据备份

SQLite 数据库为单文件，备份非常简单：

```bash
# 方法一：直接复制数据库文件
cp data/poetry.db data/poetry.db.backup

# 方法二：使用 sqlite3 的 .backup 命令（更安全，避免并发写入问题）
sqlite3 data/poetry.db ".backup 'data/poetry.db.backup'"

# 方法三：定时备份（crontab 示例）
# 每天凌晨 2 点备份
# 0 2 * * * cp /path/to/data/poetry.db /path/to/backup/poetry-$(date +\%Y\%m\%d).db
```

**备份建议：**

| 项目 | 建议 |
|---|---|
| 备份频率 | MVP 阶段数据为只读，初始化后无需频繁备份；生产环境建议每日备份 |
| 备份位置 | 本地备份 + 异地存储（如对象存储） |
| 恢复方式 | 将备份文件复制回 `data/poetry.db` 即可 |

curl -s -o /dev/null -w "%{http_code}" http://localhost:5173/

## 八、常见故障处置

### 8.1 后端启动失败

#### 故障现象：端口占用

```
Error: listen EADDRINUSE: address already in use :::3000
```

**处置方法：**

```bash
# 查找占用端口的进程
lsof -i :3000
# 或
netstat -tlnp | grep 3000

# 终止占用进程
kill -9 <PID>

# 或修改端口
export PORT=3001
npm run dev:server
```

#### 故障现象：依赖缺失

```
Error: Cannot find module 'express'
```

**处置方法：**

```bash
cd src/server
npm install
```

#### 故障现象：better-sqlite3 编译失败

```
Error: better-sqlite3 安装失败，原生编译错误
```

**处置方法：**

```bash
# 重新编译原生模块
npm rebuild better-sqlite3

# 若仍失败，检查构建工具
# macOS: xcode-select --install
# Linux: sudo apt-get install build-essential python3
# Windows: npm install --global windows-build-tools
```

### 8.2 前端启动失败

#### 故障现象：依赖缺失

```
Error: Cannot find module 'vue'
```

**处置方法：**

```bash
cd src/client
npm install
```

#### 故障现象：Vite 配置错误

```
Failed to load config file: vite.config.js
```

**处置方法：**

```bash
# 检查 vite.config.js 语法是否正确
# 确认 @vitejs/plugin-vue 已安装
cd src/client
npm install @vitejs/plugin-vue --save-dev
```

#### 故障现象：端口 5173 被占用

**处置方法：**

```bash
# 查找并终止占用进程
lsof -i :5173
kill -9 <PID>
```

### 8.3 数据库连接失败

#### 故障现象：数据库文件不存在

```
Error: ENOENT: no such file or directory, open 'data/poetry.db'
```

**处置方法：**

```bash
# 检查数据库文件是否存在
ls -la data/poetry.db

# 若不存在，重新初始化数据
npm run init-data
```

#### 故障现象：数据库文件损坏

```
Error: database disk image is malformed
```

**处置方法：**

```bash
# 1. 从备份恢复
cp data/poetry.db.backup data/poetry.db

# 2. 若无备份，重新初始化
rm data/poetry.db
npm run init-data
```

#### 故障现象：路径配置错误

**处置方法：**

```bash
# 检查环境变量
echo $POETRY_DB_PATH

# 确保路径正确且文件存在
# 使用默认路径：取消设置 POETRY_DB_PATH
unset POETRY_DB_PATH
```

### 8.4 数据导入失败

#### 故障现象：网络问题（git clone 失败）

```
Error: git clone 失败，无法下载 chinese-poetry 数据集
```

**处置方法：**

```bash
# 检查网络连接
ping github.com

# 手动下载数据集
cd data
git clone --depth 1 https://github.com/chinese-poetry/chinese-poetry.git
cd ..

# 重新执行导入（跳过下载步骤）
npm run init-data
```

#### 故障现象：磁盘空间不足

```
Error: ENOSPC: no space left on device
```

**处置方法：**

```bash
# 检查磁盘空间
df -h

# 清理不需要的文件
# 删除旧的数据集目录（如需重新下载）
rm -rf data/chinese-poetry/

# 确保至少 500MB 可用空间
```

#### 故障现象：导入中断

**处置方法：**

```bash
# 数据导入脚本支持幂等执行，可安全重试
# 删除已有数据库重新导入
rm data/poetry.db
npm run init-data
```

## 十、安全建议

### 10.1 MVP 阶段

MVP 阶段为本地运行，无公网暴露，安全风险极低。注意事项：

| 项目 | 说明 |
|---|---|
| 数据源可信 | chinese-poetry 为开源公有领域数据集，数据来源可信 |
| 无用户输入写入 | 应用为只读系统，用户搜索不会修改数据库 |
| 本地运行 | 不暴露到公网，无外部攻击面 |

### 10.2 生产环境建议

若后续将应用部署到公网，建议采取以下安全措施：

| 安全维度 | 建议措施 | 说明 |
|---|---|---|
| HTTPS | 配置 SSL 证书（Let's Encrypt 免费） | 加密传输，防止中间人攻击 |
| CORS | 配置允许的域名白名单 | 限制跨域请求来源 |
| 速率限制 | 使用 `express-rate-limit` 中间件 | 防止 API 滥用和 DDoS |
| 输入校验 | 对所有用户输入进行校验和转义 | 防止 SQL 注入和 XSS |
| 请求体大小限制 | 配置 `express.json({ limit: '10kb' })` | 防止大请求体攻击 |
| 安全头 | 使用 `helmet` 中间件 | 自动设置安全相关 HTTP 头 |
| 依赖更新 | 定期 `npm audit` 检查依赖漏洞 | 及时修复已知安全漏洞 |
| 数据库权限 | SQLite 文件设置为只读 | 防止意外写入 |

```bash
# 生产环境安全中间件安装示例
npm install helmet express-rate-limit
```

## 十一、扩展指南

### 11.1 如何添加新的 API 接口

以添加"获取热门诗词"接口为例：

**Step 1：数据访问层（DAO）**

```javascript
// src/server/dao/poem-dao.js 中添加
function getPopularPoems(limit = 10) {
  const db = require('../db/database');
  return db.prepare(`
    SELECT p.id, p.title, a.name AS author, d.name AS dynasty
    FROM poems p
    JOIN authors a ON p.author_id = a.id
    JOIN dynasties d ON p.dynasty_id = d.id
    ORDER BY RANDOM() LIMIT ?
  `).all(limit);
}
```

**Step 2：业务逻辑层（Service）**

```javascript
// src/server/services/poem-service.js 中添加
function getPopularPoems(limit) {
  const poems = poemDao.getPopularPoems(limit);
  return { list: poems };
}
```

**Step 3：路由层（Routes）**

```javascript
// src/server/routes/poem-routes.js 中添加
router.get('/api/poems/popular', (req, res) => {
  const limit = parseInt(req.query.limit) || 10;
  const result = poemService.getPopularPoems(limit);
  res.json({ code: 0, data: result });
});
```

### C. 故障排查流程图

```
服务无法启动
├── 后端启动失败
│   ├── 端口占用 → lsof -i :3000 → kill 或改端口
│   ├── 依赖缺失 → cd src/server && npm install
│   ├── 数据库不存在 → npm run init-data
│   └── better-sqlite3 编译失败 → npm rebuild better-sqlite3
├── 前端启动失败
│   ├── 端口占用 → lsof -i :5173 → kill
│   ├── 依赖缺失 → cd src/client && npm install
│   └── Vite 配置错误 → 检查 vite.config.js
└── 数据导入失败
    ├── 网络问题 → 手动 git clone 数据集
    ├── 磁盘不足 → 清理磁盘空间
    └── 导入中断 → 删除 poetry.db 后重新 npm run init-data
```
